# R0.1 — Hardening / R1 preflight

Status: **complete**.

R0.1 is a focused hardening pass after the completed R0 — Ember milestone. It does not reopen Ember standards breadth. Its purpose is to fix contracts that become more expensive to change once R1 standards-oriented parsing, style and layout work expands the codebase.

The tracking issue is #32.

## A — Public invariants and render boundary

- [x] Make DOM identifiers opaque rather than a public `usize` alias.
- [x] Add fallible DOM read/history boundaries where invalid IDs or pruned generations can currently panic; incremental consumers fall back conservatively when retained mutation history is unavailable.
- [x] Make `DisplayList` preserve command/ID invariants by construction and validate malformed external state without process aborts.
- [x] Reject negative viewport dimensions consistently.
- [x] Add a dedicated integration correctness gate so required behavior cannot silently disappear through a renamed test filter.
- [x] Reconcile contributor and metrics documentation with the current retained-paint and incremental-rendering implementation.

## B — Viewport lifecycle

- [x] Add a viewport resize/reflow path that preserves the current `Document` and render-session state.
- [x] Stop rebuilding a new `RenderSession` from the original HTML source on every viewport change.
- [x] Add regression coverage proving DOM mutations survive resize.

## C — Resource and traversal hardening

- [x] Add structural budgets beyond source bytes and framebuffer pixels.
- [x] Remove stack-overflow exposure from critical recursive traversals or enforce explicit safe depth boundaries.
- [x] Add deep-tree and no-panic regression coverage.

## D — Text complexity and Unicode foundation

- [x] Remove avoidable quadratic text paths.
- [x] Move grapheme, bidi, line-break and script behavior toward mature standards-data-driven implementations behind existing adapters.
- [x] Add long-text complexity fixtures.

## R1 preflight

- [x] Separate stylesheet-source invalidation from element computed-style invalidation.
- [x] Define connectedness-aware DOM invalidation before script-created detached nodes become common.
- [x] Document DOM arena / detached subtree / future SpiderMonkey wrapper lifetime ownership before R2.
- [x] Add incremental-versus-full differential mutation tests.
- [x] Establish a focused R1 WPT manifest and CI guard so WPT execution starts with R1 standards work rather than waiting for R6.
- [x] Add parser/render `cargo-fuzz` targets with explicit no-panic expectations and compile them in Linux CI.

## Scope boundary

WHATWG HTML breadth, standards CSS breadth, production OpenType shaping, JS/WebIDL, networking, GPU/compositor work, multi-process sandboxing, accessibility and browser UI remain on their existing roadmap milestones. R0.1 changes only the ownership, robustness, resource and verification foundations those milestones will build on.
